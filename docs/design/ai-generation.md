# AI clip generation (Magenta Studio)

Cadence can generate new MIDI clips on an instrument track, and regenerate or
extend an existing clip, using the same MusicVAE models that ship with
[Magenta Studio](https://github.com/magenta/magenta-studio). Generation is
context-aware: it listens to the project around the target position, estimates
key and chords, interprets an optional natural-language prompt, and writes a
clip that fits the surrounding material.

The implementation is native C++ inside the engine. It does **not** embed the
Magenta Studio JavaScript app, a Node sidecar or a WebView.

## User-facing flow

- **Toolbar → IA/AI** generates on the selected (or first) instrument track at
  the playhead. This is the main entry point.
- **Track header → ✨** generates a clip on that instrument track at the
  playhead. The default mode comes from the track name/instrument.
- **Piano roll → ✨** regenerates the open MIDI clip in place.
- **Clip → Generate with AI…** generates a new clip at that clip's start.
- **Clip → Regenerate with AI…** rewrites the clip in place (`replaceClip`),
  seeding the model with the clip's own notes.
- The dialog exposes mode, length (8 s / 16 s / 30 s / 45 s / 60 s),
  creativity/temperature, variations, prompt, harmonisation and
  replace-in-place. It polls the engine and shows a preview (provider, key,
  chords, note count, what audio/MIDI was heard, and a mini piano roll).
- Long requests are still generated by the fixed 4-bar checkpoints: the engine
  stitches several windows and continues each one from the previous phrase.
- **Apply** commits the result atomically: exactly one undo entry, whether it
  creates a new clip or rewrites an existing one.

## Architecture

```
Flutter UI (ai_generation_dialog.dart)
        │  start / poll / result getters / apply
        ▼
C ABI (cadence_engine.h, c_api.cpp)
        ▼
Engine (engine.cpp)          one worker thread, state machine
        ▼
ai::Service (ai_generation.cpp)
   ├── context analysis      MIDI + audio: key, chords, density, register
   ├── prompt interpretation intent flags (mode, key, density, groove…)
   ├── Magenta MusicVAE       magenta_vae.cpp (Accelerate/CBLAS)
   ├── long-form stitching    4-bar windows with continuation seeds
   ├── candidate scoring      pick the best of N variations
   └── post-processing        key snap, register, harmony, arpeggio, groove
```

### Async lifecycle

`startAiGeneration` queues a job and returns immediately. The engine snapshots
the immutable project, so the UI can keep editing while generation runs. States
are `0 idle`, `1 running`, `2 ready`, `3 failed`. A running job is joined before
the next one starts; closing the dialog cancels cooperatively. The result is
held in an engine-side slot and is consumed by `applyAiGeneration`, so applying
twice cannot duplicate a clip.

## Models

Two checkpoints from Magenta Studio's **Generate** bundle are used:

| Checkpoint | Purpose | Input | Output |
| --- | --- | --- | --- |
| `mel_4bar_med_lokl` | melody / bass / harmony | 4 bars, 90-class one-hot | 4 bars, 90-class |
| `drums_4bar_med_lokl` | drums | 4 bars, 10-class one-hot | 4 bars, 512-class |

They are plain float32 weights plus `config.json` and
`weights_manifest.json`, so inference is a small amount of matrix maths:

- BiLSTM encoder (TensorFlow.js gate/state ordering preserved),
- three-layer LSTM decoder with a 256-dimensional latent variable,
- dense layers applied as `Aᵀ · x` (TensorFlow stores `[in, out]`),
- categorical sampling with temperature,
- `encodeDecode` for context-preserving continuation/regeneration.

The native implementation was verified against TensorFlow.js on the real
checkpoints:

- `decode(z = 0, t = 0)` melody and drums produce the same note heads,
- a fixed melody encodes to the same 256-d vector (first values:
  `-0.0439321 0.0085989 0.0080654 …`).

`cadence_cli vae-test <models-dir>` prints the parity reference values and
`cadence_cli ai-test [models-dir]` exercises the whole service, async job,
apply and undo.

### Installation

```bash
./tools/fetch_magenta_models.sh
# or: ./tools/fetch_magenta_models.sh "/path/to/AI Models"
```

Default lookup order:

1. `CADENCE_AI_MODELS` environment variable,
2. `~/Music/EZMusicProduction/AI Models`.

The engine searches recursively (up to four levels), so extracting
`generate.zip` by hand also works. `aiModelAvailable(mode)` reports whether the
matching checkpoint is installed. Without it, generation falls back to the
internal procedural engine with the same analysis/post-processing pipeline.

## Context analysis

For the target track and requested window (up to 64 bars / 120 s starting at
the anchor):

- notes from all unmuted MIDI clips overlapping the window and the preceding
  four bars are collected;
- every audible audio clip in that range is mixed to mono from the decoded
  `Project.sources` (no disk I/O) and analysed with a 4096-point STFT:
  - a global chroma profile drives audio key estimation,
  - a per-bar chroma plus a low-frequency (40–260 Hz) bass profile drives
    audio chord estimation,
  - spectral flux gives onset density and spectral centroid gives brightness;
- `estimateKey` correlates a duration-weighted pitch-class histogram against
  Krumhansl–Kessler major/minor profiles, with extra weight on downbeats and
  bass notes. Audio wins when MIDI is missing/sparse or ambiguous, and boosts
  confidence when both agree;
- `estimateChord` fits major/minor/diminished triads per bar from MIDI, using
  chord-tone energy, a bass-root bonus and a non-chord-tone penalty. If the bar
  has too little MIDI, the audio chroma + bass profile is used instead;
- `refineKeyWithChords` disambiguates relative keys (C minor vs E♭ major) by
  scoring which candidate key makes the measured chords diatonic, plus a tonic
  bonus for the first bar;
- when the window is empty and there is no audio, a default i–VI–III–VII
  progression in the detected key is used;
- density, median register, target role (melody/bass/harmony/drums) and
  neighbouring motifs come from the same notes; audio onset density and
  centroid fill in when the MIDI window is empty.

The result reports what it heard (`contextNote` in the C ABI), for example
`heard 8.0s of audio (C minor) · 0 MIDI notes in window · 4 bars / 8.0s`.

Chord and key names use the key signature's spelling, so C minor reads
`Cm | Ab | Eb | Bb` rather than sharps.

## Prompt interpretation

The prompt is optional and free text (Spanish or English). Tokens are matched
case-insensitively and accent-insensitively enough to accept stems:

- mode override: `drum`, `bater`, `perc`, `bass`, `bajo`, `contrabaj`,
  `chord`, `acorde`, `harmony`, `armonía`, `pad`, `melody`, `melodía`, `lead`;
- key: note names (`Do`, `Re`, `Mi`, `Fa`, `Sol`, `La`, `Si` plus `C`…`B`),
  optional `m`/`min`/`maj`, and `menor`/`minor` / `mayor` / `major`;
- density: `menos`, `sparse`, `pocas` vs `más`, `dense`, `muchas`;
- register: `agudo`, `alto`, `high` vs `grave`, `bajo`, `low`;
- colour: `oscuro`, `dark`, `triste` forces minor; `alegre`, `bright`
  forces major;
- harmony/arpeggio/groove: `armon`, `acorde`, `arp`, `swing`, `groove`,
  `human`, `velocidad`.

The interpreted intent is echoed back to the UI (`promptNote`), and it biases
temperature, density, register, harmonisation and arpeggiation. A key named in
the prompt overrides the measured key; a mode implied by the prompt overrides
the dialog's mode.

## Generation

### Model path

The checkpoints are fixed at 4 bars, so a request is split into 4-bar windows.
For each variation (`1–8`, capped at 3 above 4 bars and 2 above 8 bars so a
one-minute job still finishes quickly):

- the first window uses the project seed (surrounding MIDI / the clip being
  regenerated) with `encodeDecode(seed, temperature, similarity, seed + 7919·v)`;
- later windows use the previous generated 4 bars as the seed, with a lower
  similarity for melody/bass and a higher one for drums (or when replacing a
  clip), so the line develops instead of restarting;
- if a window has too little seed material, a fresh `sample(...)` is drawn;
- only the bars inside the requested duration are kept, and every note is
  trimmed to the exact length (for example 30.00 s);
- candidates are scored for key/chord fit, register, density match, melodic
  leaps, repetition and contour, and the best one wins.

The chosen seed is returned so a result can be reproduced. Post-processing also
pulls strong-beat notes to the bar's chord tone when they are within a few
semitones, which keeps long model output harmonically anchored.

### Procedural fallback

When no checkpoint is installed (or `useModel` is false), the same analysis and
post-processing run on a deterministic generator per mode:

- melody: two motif-based phrases (A/B) with chord-tone anchoring,
  transposition across phrases and contour inversion every fourth phrase,
- bass: root/fifth patterns locked to the chord progression, with an octave
  lift at phrase ends,
- harmony: chord beds with optional arpeggios,
- drums: style-dependent kick/snare/hat patterns with velocity accents and
  phrase-end fills.

### Post-processing

All paths share:

- **key snap** to the detected or prompted scale (natural/harmonic minor),
- **register fit** around the target track's median pitch / role range,
- **harmonisation** by adding chord tones below the lead,
- **pad** and **arpeggio** realisation from the chord progression,
- **groove**: swing, humanised timing/velocity, accents on beats,
- **density** shaping and note-length cleanup,
- clamping into the clip length and MIDI range.

The target track's instrument plug-in and FX are never modified. The engine
derives the musical role from the track name/instrument and generates into that
register; choosing a different instrument for the result is intentionally out
of scope for now.

## API summary

C ABI (`engine/include/cadence/cadence_engine.h`):

- `cadence_engine_set_ai_model_dir`, `cadence_engine_ai_model_dir`,
  `cadence_engine_ai_model_available`
- `cadence_engine_start_ai_generation(track, clip, anchor, mode, bars,
  temperature, variations, seed, prompt, replace, harmonize, use_model)` —
  legacy 1–4-bar entry point;
- `cadence_engine_start_ai_generation_long(track, clip, anchor, mode, bars,
  length_seconds, temperature, variations, seed, prompt, replace, harmonize,
  use_model)` — exact duration up to 120 s, generated in 4-bar windows;
- `cadence_engine_ai_generation_state`, `cancel`, `clear`
- result getters: `ok`, `string(field)` (field 5 is the heard context),
  `seed`, `clip_length`, `start`, `clip_id`, `track_id`, `note_count`,
  `note_at`
- `cadence_engine_apply_ai_generation`

Dart counterparts live in `ui/lib/engine/cadence_bindings.dart`, with the
higher-level polling/apply flow in `ui/lib/engine/engine_service.dart`.

  `ozone_track7` tests depend on installed plug-ins and are environment-heavy).
